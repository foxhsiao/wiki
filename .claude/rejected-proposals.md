# 被否決的提案

考慮過、**沒有採用**的東西：規則、流程改動、結構調整、被推翻的假說。
被採用的規則記在 `.claude/rules-ledger.md`，這裡記的是另一半。

## 為什麼要有這一份

`Wiki/log.md` 記做了什麼，`rules-ledger` 記被採用的規則為什麼在。
兩者都不記**被丟掉的東西**，所以同一個已經被否決的主意可以被反覆提出，
每次都要重新論證一遍。

來由是 `Wiki/sources/wikiskill.md`：它的 `skill-impact.md` 把每個提案的 diff、
驗證分數與接受結果都留在永不回滾的那一層，原文給的第一個用途是

> "observe the complete skill acceptance history so that **rejected interventions are not
> proposed again**"

完整比對見 `Wiki/syntheses/two-wiki-architectures.md`。

## 怎麼用

- **提出任何規則或流程改動之前先讀這一份。** 如果提案已經在表裡，
  除非「什麼會讓它重新成立」那一欄的條件已經滿足，否則不要重提。
- 否決一筆就當場補一列（`[W9]`）。事後補不回來——這是 Q10 的教訓。
- **這一份是保留型**（`[L5]`）：只增不改。決定被推翻時加新的一列註明，不要改舊列。
- 「什麼會讓它重新成立」不能留空。寫不出重新成立的條件，表示這不是一次判斷，
  是一次偏好——那種東西不該進這張表，該直接寫成規則或直接放棄。
