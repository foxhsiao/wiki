# llm-wiki 健檢

先跑 `python3 tools/lint.py` 取得機械性問題（frontmatter 欄位、斷鏈、孤兒、出鏈數、index 漏登、
Raw 未 ingest、Wiki/ 以外的走失頁、規則來由缺漏），再由你做下面這六項判斷性檢查。

## 六項判斷性檢查

- **矛盾**：不同頁對同一件事說法不一致。
- **過期**：新來源已推翻舊主張，但舊頁沒改（`status: stale` 卻沒人處理）。
- **孤兒**：沒有入鏈的頁。
- **缺頁**：被反覆提及卻沒有專頁的概念。
- **證據薄弱**：`confidence: low`，或只靠單一來源撐起的重要主張。
- **缺口**：可以靠一次網路搜尋或一份新來源補起來的空白 → 主動提議該找什麼。

## 輸出方式

輸出成一份問題清單，**逐項問使用者要不要修，不要擅自大改**。
log 的動作標 `lint`。

## lint 抓得到什麼（已證明）

`python3 tools/test_lint.py` 是 lint 的**反向對照**：
它在暫存目錄建一個基準線全綠的最小 fixture，逐一注入 15 種已知缺陷，
斷言 lint 回報對應的標記。**15 種全部通過。**

所以「lint 全綠」現在有了一半的保證：**這 15 類缺陷確實會被抓到**——
frontmatter 缺欄位／type 不合法／斷鏈／孤兒／出鏈不足／index 漏登／走失頁／
衝突標記／規則沒補來由／新規則沒寫預期效果／證據等級不合法／
high 但來源不足／type 與資料夾不符／空區塊／Raw 未 ingest。

改動 `tools/lint.py` 之後要重跑這支測試。

## lint 不涵蓋什麼（另一半，要自己看）

**lint 檢查的是形式，不是內容。** 全綠**不**代表下面任何一項成立：

| 不涵蓋 | 說明 |
|---|---|
| **引文與數字是否照抄無誤** | `[S2]` 完全靠自覺。抄錯一個數字 lint 不會知道 |
| **來源頁是否忠實於原文** | 摘要扭曲原意，形式上完全合法 |
| `sources` **列的來源是否真的支撐該頁主張** | 只檢查欄位非空，不檢查相關性 |
| **連結是否連對頁** | 只檢查目標存在。連到錯的頁一樣全綠 |
| `confidence_note` **的理由是否成立** | 只檢查存在，不檢查合理 |
| 「防什麼」與「預期效果」**的內容品質** | 同上，只檢查存在與格式 |
| **頁面內容是否過期** | 只看 `status: stale` 這個人工標記 |
| **矛盾、缺頁、證據薄弱、缺口** | 本檔開頭那六項判斷性檢查，刻意留給人做 |
| `Raw/` **的內容** | 刻意不掃——`[L1]` 唯讀 |
| **Obsidian 層面** | 關聯圖、附件、每日筆記等不在範圍 |

## 殘餘的盲點（Q13 沒有被完全解決）

反向對照只證明 **lint 抓得到我想到的那 15 類缺陷**。
**沒有人想到的缺陷仍然是隱形的**——2026-08-29 那次 `_to_delete/` 裡躺著 7 個重複頁，
lint 全綠，是使用者從關聯圖看出來的。那一類缺陷在被想到之前，測試也測不到它。

所以判讀「全綠」的正確說法是：
**形式無誤，而且這 15 類缺陷已被排除。其餘一概未知。**

懷疑漏東西時，換一個視角看：關聯圖、`find` 全庫、或直接讀 `Wiki/log.md` 對照。

## lint 本身的盲點

`tools/lint.py` 全綠**不代表庫是健康的**，只代表機械性檢查沒抓到東西。
它的檢查範圍本身就是盲點的來源——2026-08-29 那次就是使用者從 Obsidian 關聯圖看出
vault 裡躺著 7 個重複頁，而 lint 當時全綠（見 `Wiki/questions/open-questions.md` Q13）。
懷疑漏東西時，換一個視角看：關聯圖、`find` 全庫、或直接讀 `Wiki/log.md` 對照。
